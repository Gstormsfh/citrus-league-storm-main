## Night 2 — the load campaign, and two platform-grade finds
**Aug 10/11 · Entries 97–115. The longest single stretch of the three.**

**LOAD-1-NIGHT** ran to Garrett's order: a load and latency certification campaign, architect-solo at ~15-minute cadence, with the terminal standing up mid-campaign as the WebSocket muscle (E97, E98). **86 drafts.** The spine held at **p95 11.6ms** with 8 simultaneous drafts.

Two findings from that campaign were platform-grade:

**COMPLETED-ROOM-2 (E99)** — the completion loader hung because the engine's serializer reported `draftStatus: 'in_progress'` for a league whose durable log already carried `draft_completed`. A dual-source-of-truth bug: the projection and the snapshot disagreed, and the client believed the wrong one.

**IGNITION-RACE (E100)** — concurrent `start_draft_v2` calls produced **multiple `draft_started` events for one league.** Found by the same-league contention rung of the load campaign, which is exactly the rung that exists to find it. Migration authored, applied by the architect, and **field-proven by re-running the race** (E102).

Then the merge: **`f70c5f87..88e68529`, fast-forward clean** — two nights of work onto the trunk (E107).

**ENGINE-EAR v3 Slice 1** followed, and it took **three hotfixes to land** (E108–E115), each one worth remembering because each was a different class of mistake:

| # | defect | class |
|---|---|---|
| E109 | unbound `.from` TypeError killed both new code paths — `const untypedFrom = supabase.from` loses `this` | JS semantics; the boot log was the proof |
| E111 | the boot scan queried `draft_status = 'paused'` — **a value that enum does not contain** (`paused` lives on `draft_state`) | schema/domain; **mocked DB stubs accepting arbitrary literals cannot catch this** |

## Day 3 — the strategic find, and the two draft-quality fixes
**Aug 11 · Entries 116–122**

**E116 — PRODUCTION HAS NO V2 DRAFT SYSTEM.** An autonomous audit against both live databases: prod has **zero of three** v2 tables, **zero of three** v2 functions, **zero** of the twelve v2 migrations, and **no engine VM**. Staging has all of it. This turned "where do the twelve draft" from an assumption into a live decision with a nine-day clock. Full evidence in `PROD_READINESS_GAP_ANALYSIS.md`; the runbook's own header already said staging, so the plan of record and the recommendation agree.

**E117 — autopick was ranking by a per-game rate.** It would have taken backup goalies in round one. Fixed to rank by expected season value (`ppg × expectedGames`). **E118 — roster-shape guard**: position caps so no manager can be handed twelve goalies. **460/460 draft tests, tsc 0.**

**E119 — the discipline entry.** "Drafted By 77777777" looked like a product bug; a control league proved real names render. **It was a rig artifact, closed with evidence instead of a needless fix.** This is the entry that pays for itself every time someone is tempted to fix a symptom.

**E120/E121 — TIMER-1.** Garrett's 0:35-on-a-30s-clock. Root cause: both of E104's mechanisms read `snapshot.recentEvents`, and the engine's ring buffer holds **pick events only** — so a freshly-ignited draft has an empty buffer and the opening pick gets zero skew correction. Fixed by seeding from the **HTTP `Date` response header** plus half the round trip: no engine change, no wire-version bump, works on the very first snapshot. **16/16 + 24/24 + 10/10.**

## Three lessons that changed how the work was done

**1. Measure from the page's clock, never from the tool's.** Two latency figures — **13.8s** (ignition→enter) and **9.9s** (rejoin→render) — were plausible, alarming, and wrong. Both were my own instrumentation's round-trip, not the product's behaviour. Both were caught and retracted **before** they entered a document Garrett would act on (E127, E136). The fix each time was the same: read `performance` and the resource timeline, which are measured from navigation start and do not care when the observer attached.

**2. Before writing "one-line fix" in a ledger, open the line.** Three times a confident, plausible remedy was wrong in a way only the source or the schema could reveal: `player_season_stats` carries **two parallel stat families that disagree on 738 of 1,066 rows** (E132); there is **no foreign key** between the directory and the stats table, so the single-query fix I recommended does not exist (E132); and `setActiveLeagueId` is **a full league-switch ceremony that would have nulled `activeLeague` at draft-room mount** (E137). It reads like a setter because it is named like one.

**3. A plausible default is more dangerous than a missing one.** `DraftBoard`'s `totalRounds = 16` produced "252 of 192 picks made" for three days without anyone noticing, because 16 is a reasonable number. A required prop would have failed at the type level the instant the port omitted it. The same shape appears in `dataFreshnessLabel`, which reads *"no player has stats"* as *"it must be the offseason"* and **actively reassures the user that the bug is normal** (E131).

The corollary — **diff the call sites, not the components** — produced `V2_PORT_GAP_REGISTER.md`: eleven rows, found in ten mechanical minutes, after three of them had each been found by accident over four hours (E135).
