## Downstream boundary review (read-only)

Three concrete follow-ups remain separate from the database proof:

1. `data-pipeline/projections/calculate_daily_projections.py:2811` onward builds replacement level without season/date/horizon filters and ranks projection rows rather than unique player-horizon candidates. The shared accumulated-result quota at line 2865 can prevent later ID batches from being queried after an earlier batch fills the quota; sorting the accumulated subset cannot restore omitted players. The league VOPA caller at line 3027 inherits this. A bounded fix should require explicit season/horizon, complete eligible candidate membership and unique player projections before global ranking, with tests for a better player in a later batch, duplicate historical dates, and unavailable source coverage. This is not a validated FPAR or feasible multi-position roster-allocation model.
2. Python point helpers at lines 1623 and 2568 omit plus/minus, while `packages/shared/src/utils/scoring.ts:99` supports a nonzero league plus/minus weight. The current physical forecast does not provide a plus/minus prediction. A safe next contract is explicit unsupported-category/unavailable scoring for such a league until the component exists, plus cross-language scoring parity tests; silently inserting a forecast of zero would conceal the gap. Generated default weights do not by themselves prove equivalent scoring logic.
3. `server/src/services/PlayerDashboardService.ts:878` defaults missing `x_goals` to zero. `DraftKitService.ts:688` then calculates finishing as actual goals minus xG whenever games played is positive. Missing xG coverage can consequently appear as positive measured finishing. A nullable xG coverage/status boundary and missing-versus-measured-zero regression would be narrower than changing metric math. Existing season filters on GAR/GSAx reads are present and should be preserved.

Neutral event probability, descriptive xG totals, persistent finishing/goalie effects, GAR rates and fantasy forecast components have different meanings and units. The search found no executable FPAR implementation under that name; the preservation document correctly requires validated forecasts, eligibility, horizon, replacement opportunity and feasible roster allocation. None of these follow-ups authorizes replacing official actuals with PBP-derived values or relabeling GAR as league-specific fantasy points.
