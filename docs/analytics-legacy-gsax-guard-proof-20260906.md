The safeguard rejects empty source, unresolved/unscored recorded shots, missing/extra goalie membership, inconsistent attempts/SOG/goals/xG/GSAx, missing SOG exposure, and cross-season key collisions before deleting anything. With no explicit season, the latest aggregate season must match the latest recorded regular-season shot season. Floating-point sum reconciliation permits only a relative `1e-8` rounding tolerance. DELETE is constrained to the requested season.

Production's output key is `PRIMARY KEY(goalie_id)`, not `(season,goalie_id)`. A returning goalie already stored for another season therefore causes a clear failure that leaves all existing rows intact. This intentionally blocks rollover/backfill until a separately designed season-key migration; multi-season storage is not solved here.

Consistency reasoning: only READ COMMITTED is accepted. The function first acquires SHARE table locks on `nhl_shots` then `goalie_xg_season`, and SHARE ROW EXCLUSIVE on its output. These persist through the surrounding transaction, block source DML and concurrent output writers, and keep the subsequent source checks and existing math tied to one stable population. Ordinary SELECT remains permitted. Existing callers that already hold source write locks may contend or deadlock; PostgreSQL then aborts one transaction rather than publish an unchecked result. This guard can delay ingestion/other analytics writes, so staging concurrency and load evidence are required before applying it. No native multi-connection proof is claimed from PGlite.

Coverage limit: reconciliation proves completeness relative to the recorded eligible regular-season `nhl_shots` population. It cannot discover games absent from that corpus, verify official source completeness, or establish immutable scorer/model lineage; those require the separate canonical observation/publication contracts. It does not certify legacy projections as fully verified.
