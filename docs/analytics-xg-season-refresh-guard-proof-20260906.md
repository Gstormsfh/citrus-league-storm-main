# Recorded xG season refresh guard — 2026-09-06

Status: local and unapplied. Production was read only to capture `refresh_xg_season_layer(integer)`, its security mode and EXECUTE ACL. The original body MD5 is `4ed76fd708c6ff03c79891241f9dd7ce`. The migration refuses a different live definition; exact rollback source is in `supabase/migrations/captures/2026-09-06_pre_guard_xg_season_refresh_inputs.sql`.

Before any existing refresh operation, the guard requires an explicit season and READ COMMITTED isolation. It rejects a requested season with no recorded row eligible for at least one existing entity aggregate (shooter, team, or non-empty-net goalie). It then rejects any requested-season recorded row whose `xg_sql` is NULL, nonfinite, negative or greater than one. Valid zero and one probabilities remain accepted. Invalid records from another season do not block the requested refresh. An unscored row cannot hide behind a missing shooter or the existing downstream filters.

The guard acquires a SHARE table lock on `nhl_shots`, followed by SHARE ROW EXCLUSIVE locks on `goalie_xg_season`, `player_xg_season` and `team_xg_season`. Source-first/goalie-second ordering agrees with the GSAx guard. These locks last through the outer transaction: source DML cannot change the checked population, and output writers cannot interleave the destructive refresh. READ COMMITTED prevents reusing a snapshot established before waiting for those locks. Ordinary reads remain possible. Whole-table locking can delay ingestion or contend with existing callers that already hold write locks; deadlock rejection is fail-closed. This isolated proof does not replace native concurrency/load checks before rollout.

All original aggregation SQL, season-scoped deletes, output columns, signature, SECURITY DEFINER mode, search path and EXECUTE privileges are retained. There is no new game-type or shootout filter: the original function aggregates the requested season and groups whatever game types are recorded. Existing missing-shooter and non-empty-net/goalie filters remain intact. The legacy SOG expression counts every event labeled `goal`, including its known awarded-goal limitation; this change does not certify official SOG correctness. No scoring math, talent logic or GAR logic is changed.

The inherited scratch cleanup is narrowed from `DROP TABLE IF EXISTS _sides` to `DROP TABLE IF EXISTS pg_temp._sides`. This prevents a persistent `public._sides` table from being resolved and dropped when no temporary relation exists. Aggregation arithmetic is unchanged.
