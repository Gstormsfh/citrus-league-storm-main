# Dynamic player outlooks

Standing forecast outlooks use `seasonOutlookWriteup`; historical card assessments retain `profileWriteup`. Both accept dated, identity-matched reporting. Forecast totals, maintained availability, current affiliation and historical seasons come from their existing governed services. Editorial rendering does not change projections or league scoring.

`GET /api/news/player/:playerId` evaluates the standing outlook from the current dashboard publication and stored news on every request. The dashboard index has a two-minute data cache and checks the canonical revision. News ingestion runs every 30 minutes; source publication, ingestion, evaluation and original note publication are distinct clocks. Build 19 and current web poll notes every 60 seconds while open. Build 18 supports remote prose on its next fetch/open, but its archived hook has no interval; it cannot gain polling or new source-link UI through this backend change.

The six-hour generation job persists the complete available canonical corpus, including explicit unallocated-opportunity outlooks. It reads all source pages, upserts materially changed revisions, retains original `published_at`, and records `updated_at`, `editorial_version`, `content_revision` and `source_context`. Identical repeats skip writes. Notes outside the successful current-season corpus are marked `is_current=false`; their prose remains available for audit. A failed source read prevents retirement. Historical event notes retain their immutable dedupe behavior.
