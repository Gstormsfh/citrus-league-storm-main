AUC-ROC: 0.817
Area Under the Receiver Operating Characteristic curve. Measures discrimination ability — can the model distinguish shots that score from shots that don’t? 0.5 = random, 1.0 = perfect. 0.817 is top-tier for NHL xG models.

Mean squared prediction error: BS = mean((xG − actual)²). Lower is better. 0.054 means our probability estimates are extremely well-calibrated. A model predicting 8% xG should see ~8% of those shots score.

Probability Calibration
Predictions are bucketed into deciles and compared against actual goal rates. Our calibration curve closely tracks the diagonal (perfect calibration). Shots predicted at 10% xG score ~10% of the time.

What Brier Score 0.054 Means in Practice
For context: a naive model predicting the NHL-average goal rate (~9%) on every shot achieves a Brier score of ~0.082. Our 0.054 represents a 34% improvement over the naive baseline. The theoretical floor (perfect prediction) is ~0.040 for NHL shots due to inherent randomness. We capture the vast majority of the predictable signal in shot quality.

BrierTracker — Win Probability Calibration

Tracks prediction quality per league per week • Bucketed calibration curves • Stored in simulation_brier_scores
NEW
Brier Score Formula
BS = mean((predicted_prob − actual_outcome)²)
Each matchup produces a win probability (e.g., 0.72). After the week completes, actual outcomes (1 = win, 0 = loss) are compared. The squared difference is averaged across all matchups in the week.
Example: We predicted 72% win chance → team actually wins → (0.72 − 1)² = 0.0784. Predicted 35% → team loses → (0.35 − 0)² = 0.1225. Average across all matchups in the week.

Calibration Bucket Analysis
How Bucketed Calibration Works
Win probability predictions are grouped into 10 buckets (0–10%, 10–20%, ..., 90–100%). For each bucket, we compare the predicted average against the actual win rate.

A well-calibrated model has predicted ≈ actual in every bucket. If we predict 70% win chance for a group of matchups, approximately 70% should actually be wins.

This is stored per league per week in simulation_brier_scores.calibration_data (JSONB) for historical tracking and model improvement.

NEW
90% CI Coverage
The 90% confidence interval (5th–95th percentile) should contain the actual fantasy score 90% of the time. If it contains only 75%, the intervals are too narrow (overconfident). If 98%, too wide (underconfident).

Target: 88–92% actual coverage.
Coverage Check
50% CI Coverage
The 50% CI (25th–75th percentile) should contain actuals 50% of the time. Displayed to users as "Likely: X.X – Y.Y pts". This is the most user-visible accuracy metric.

Target: 48–52% actual coverage.
User-Facing
Upside/Floor Accuracy
upside_probability = P(actual > 1.5× projection). floor_probability = P(actual < 0.5× projection). These should match observed rates — if we say 15% upside chance, ~15% of the time the player should exceed 1.5×.
Tail Accuracy
Dynamic Confidence
CV = σ/μ, Confidence = 1 − CV. Validated that high-confidence players (≥0.60) have tighter actual outcome distributions than low-confidence players (<0.35). The label should match real-world variance.
Validated
Validation Methodology
Backtest approach: Run projection_uncertainty.py on historical game dates where actual outcomes are known. For each player-game, check whether the actual fantasy score falls within the predicted confidence intervals. Aggregate coverage rates across thousands of player-games.

Key insight: Because we use Bayesian finishing posteriors (Beta-Binomial) and opponent strength distributions with proper standard errors, our CIs naturally widen for uncertain players (rookies, injury returns) and narrow for established veterans with 50+ game track records.

Correlation validation: The 8×8 inter-stat correlation matrix is validated by comparing sampled stat covariances against actual 2023–2025 NHL per-game covariances. Cholesky decomposition preserves the positive semi-definite structure.

Data Pipeline Integrity

Source hierarchy • Cross-validation • Freshness monitoring • PPP/SHP reconciliation
Audited
Source Hierarchy (no ambiguity)
1. NHL Landing Endpoint — Season totals for PPP/SHP. Single authoritative source. Updated at midnight MT.

2. NHL Game-Log API — Per-game PPP/SHP. Used for daily breakdowns only.

3. NHL Boxscore API — Live in-game stats (goals, assists, SOG, blocks, hits, PIM). 30s intervals.

4. Play-by-Play API — Event-level data for xG features, shift overlaps, assist chains.
4-Tier Hierarchy
PPP/SHP Reconciliation
The #1 accuracy problem in fantasy hockey: power play points. Different NHL API endpoints give different numbers.

Citrus solution: Season PPP/SHP totals come exclusively from the Landing endpoint. Per-game PPP/SHP from Game-Log API for daily breakdowns. Never aggregate per-game to season (introduces drift). Nightly reconciliation job verifies totals match.
Reconciled Daily
Freshness Monitoring
check_data_freshness.py runs hourly. Checks:

• player_game_stats: <5 min for active games
• player_season_stats: <24 hours
• player_projected_stats: <24 hours
• matchup_simulations: <60 min (staleness check)

Alerts on stale data. Auto-triggers resync on failure.
