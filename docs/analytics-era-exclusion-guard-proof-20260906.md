# Era/playoff exclusion safeguard — 2026-09-06

Status: local and unapplied. Production was read only to recapture the exact function and ACL. Original `citrus_fit_xg_v5_era(numeric,integer[])` body MD5 is `f561319c1b8dcc9ea17b3330cdc94af5`; the migration checks that pin before replacement. Its exact same-day rollback definition is `supabase/migrations/captures/2026-09-06_pre_guard_xg_era_fit_exclusions.sql`.

The original exclusion predicate applied only to regular-season aggregation. Playoff fitting still read excluded seasons, and an empty/nonpositive eligible playoff expectation could leave the prior singleton fit alongside a newly rebuilt era table. The safeguard filters the shared scored-row relation before either aggregation. Both the regular era and pooled playoff outputs therefore use the same exclusion set.

The function now refuses an empty eligible regular **or** playoff population before either persistent fit table changes. It also refuses nonpositive eligible playoff expectation. Abort preserves the prior era and playoff tables together, including their original fitted timestamps; it does not report stale playoff state as freshly fitted. Consequently a legitimate dataset without playoff data cannot use this combined fitter successfully. Supporting regular-only fits requires a separate explicit missing-playoff contract, which is outside this change.

The playoff candidate is calculated before deletion against the newly computed era candidates, rounded to the same six decimal places as the stored era multipliers. The prior eligible arithmetic, fallback for an unmatched era cell, output signature, INVOKER security, search path, and EXECUTE ACL are preserved. A NULL exclusion array keeps the prior meaning of “exclude none”; arrays containing NULL elements are rejected instead of allowing SQL `ANY` three-valued logic to silently change the population. Duplicate or absent season values are harmless membership exclusions and retain existing behavior.

The shared scored-row materialization reads source/base/moat/shape inputs in one SQL statement. Subsequent fits derive from that temporary relation. This change introduces no new concurrency mechanism and supplies no native multi-connection fit proof. Existing caller transaction behavior still applies; repeated fits within one explicit transaction can encounter the existing temporary-table-name restriction.

`scripts/test_xg_era_fit_exclusions.mjs` passes 15 isolated PGlite checks: it reproduces the old playoff-exclusion bug; verifies both output populations after exclusion; changes excluded rows without changing either fit; checks unchanged no-exclusion arithmetic; compares the corrected excluded result with the exact original function run on physically eligible-only rows; verifies empty regular/playoff and zero-expectation rejection with unchanged prior rows/timestamps; rejects NULL array elements; preserves NULL-array compatibility, function ACL and invoker behavior; and restores the exact original function hash.

Scope limit: base/moat/shape coefficients are inputs to this function. Their own training populations are not refitted or validated here, and may have seen excluded seasons. These synthetic checks therefore establish this function's exclusion semantics, not end-to-end chronological calibration, held-out evaluation independence, model quality, or deployed metric accuracy. No scorer, fit RPC, hosted DDL, or production row mutation was executed during this work.
